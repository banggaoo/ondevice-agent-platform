## Project Proposal: ondevice-agent-platform
An Edge-Native, Self-Optimizing Agent Serving & Resource Management Infrastructure for macOS
------------------------------
## 1. Executive Summary
The ondevice-agent-platform is a macOS-exclusive background service and orchestration framework designed to deploy, run, and optimize targeted agent harnesses using Apple Silicon. On-device LLM loops strain resources, leading to Unified RAM exhaustion, high thermal loads, and heavy battery consumption. This platform reduces local compute overhead via a bidirectional optimization lifecycle (LLM ⇄ ML ⇄ Tool), systematically shifting expensive LLM steps to native code tools or lightweight CoreML models based on real-world usage logs.
To protect the local machine, the platform removes any external model discovery, web scraping, or automatic web-based upgrades. It introduces a defensive runtime guard: the on-device Operator Agent (powered by a low-overhead, quantized Qwen 3.8 9B Q4 Distill model) cannot alter the system configuration directly. Instead, it writes structured, markdown-formatted technical proposals. It then interfaces with the developer via the web console chat to request confirmation. Once permitted, actual modifications are securely offloaded to an external frontier model agent or human reviewer, ensuring local integrity and safety.

## 3. Key Architectural Pillars## 🎛️ Hardware Guard & Late-Night Execution Scheduler
Heavy operations like model training, distillation, and structural workspace optimization consume significant processing power. The resource manager strictly schedules these tasks to avoid harming local hardware:

* Idle Late-Night Windows: Self-improvement calculations, local distillation jobs, and performance audits are locked to run late at night when no real-time agent requests have been received for a sustained period.
* Thermal & Memory Gating: If memory utilization exceeds 85% or the Apple Silicon SoC temperature crosses 82°C, the platform pauses background work and holds tasks in a deferred queue until the machine cools down.
* Volatile Model Eviction: Models that sit idle past a configurable timeout window are safely offloaded from the unified memory layer, clearing active KV caches to ensure smooth operation of the primary macOS workspace.

## 📝 Proposed Change Framework (Indirect Modifications)
Because the local Operator Agent uses a compact, low-resource model, it does not possess direct privileges to edit system architectures or configurations.

* Proposal Generation: For tasks involving critical optimizations or systemic workspace modifications, the Operator Agent writes a technical markdown report detailing the proposed system patches.
* Permission Requests: The agent transmits the proposal payload directly to the frontend web terminal, holding the execution thread until the human user confirms or passes the patch to an external frontier model to execute the changes.

## 4. Implementation: Inter-Agent Permission & Safety Graph
This LangGraph script handles the safety pipeline. It evaluates the complexity of a task, blocks direct execution if a change is significant, generates a markdown change proposal, and pushes a request notification straight to the user terminal chat:

from typing import Dict, Any, Literalfrom pydantic import BaseModelfrom langgraph.graph import StateGraph, END
class ProposalState(BaseModel):
    task_id: str
    proposed_change: str = ""
    is_significant: bool = False
    user_approved: bool = False
    execution_status: str = "pending"
class SafetyOperatorHarness:
    async def analyze_task_gravity(self, state: ProposalState) -> Dict[str, Any]:
        """Evaluates if the requested task changes system behavior or configuration."""
        # Significant criteria: changing models, training pipelines, or runtime boundaries
        if "update_registry" in state.task_id or "modify_core_config" in state.task_id:
            return {"is_significant": True}
        return {"is_significant": False}

    async def generate_proposal_report(self, state: ProposalState) -> Dict[str, Any]:
        """Low-performance local model generates a patch proposal rather than editing files directly."""
        markdown_proposal = f"""
        ### System Patch Proposal: {state.task_id}
        * **Rationale:** Local optimization request triggered by performance metrics.
        * **Action Items:** Adjust optimization mapping parameters inside registry.json.
        * **Safety Warning:** Requires verification by external frontier model or human review.
        """
        # Save directly to the local file system
        with open(f"./workspace/code_proposals/{state.task_id}.md", "w") as f:
            f.write(markdown_proposal)
            
        # Trigger an internal notification message via the Web Console Chat interface
        await push_notification_to_console_chat(
            agent_id="Operator_Agent",
            message=f"I have generated a system patch proposal for {state.task_id}. Please review in the Console."
        )
        return {"proposed_change": markdown_proposal, "execution_status": "awaiting_user"}

    async def execute_via_frontier_agent(self, state: ProposalState) -> Dict[str, Any]:
        """Only executed if confirmation is obtained. Delegates modification outward."""
        if state.user_approved:
            print("🚀 Dispatching verified change proposal to External Frontier Agent...")
            # Outward API handoff happens here
            return {"execution_status": "completed_by_frontier"}
        return {"execution_status": "rejected_or_aborted"}

# Build the stateful safety graph structuresafety_builder = StateGraph(ProposalState)
operator = SafetyOperatorHarness()
safety_builder.add_node("analyze_gravity", operator.analyze_task_gravity)
safety_builder.add_node("generate_proposal", operator.generate_proposal_report)
safety_builder.add_node("dispatch_frontier", operator.execute_via_frontier_agent)
safety_builder.add_node("direct_local_tool", lambda state: {"execution_status": "completed_locally"})

safety_builder.set_entry_point("analyze_gravity")

safety_builder.add_conditional_edges(
    "analyze_gravity",
    lambda state: "generate_proposal" if state.is_significant else "direct_local_tool",
    {"generate_proposal": "generate_proposal", "direct_local_tool": "direct_local_tool"}
)

safety_builder.add_conditional_edges(
    "generate_proposal",
    lambda state: "dispatch_frontier" if state.user_approved else "end_loop",
    {"dispatch_frontier": "dispatch_frontier", "end_loop": END}
)

safety_builder.add_edge("dispatch_frontier", END)
safety_builder.add_edge("direct_local_tool", END)
safety_runtime = safety_builder.compile()

## 5. Web Console Standalone Layout
The separate web interface interfaces with the platform core server via JSON-RPC over WebSockets:

* 📊 Overview Tab: Displays unified RAM usage and CPU/GPU temperatures, highlighting the Platform Efficiency Index and the state of the late-night batch processing scheduler.
* 🤖 Models Tab: Displays active frameworks (MLX vs CoreML) and provides manual controls to flush individual model assets from system memory.
* 📜 History Tab: Reads log metrics straight from the local file system directory, tracking structural paths, self-evaluation scores, and custom optimization histories.
* 🏋️ Train Tab: Manages background dataset compilation for custom text and image fine-tuning scripts, scheduling optimization jobs for late-night windows to avoid affecting daytime performance.
* 💬 Chat Tab: The central terminal communication channel. The local Operator Agent uses this view to share generated markdown proposals, request execution permission, and coordinate modifications with external frontier services.
